# Реалістичні жуки для Claude Code та ChatGPT Codex

Фотореалістичне зображення гнойових жуків із деталізованою фактурою хітину та землистою кулькою. Claude Code має бронзово-мідний хітин; ChatGPT Codex — темний хітин із зеленуватим металевим відливом. Палітри — авторська стилізація під вендорів. Риси й пропорції комах подані в реалістичному стилі, без людської міміки.

## Що в наборі

- `claude-code.png` — прозорий PNG-атлас Claude Code.
- `chatgpt-codex.png` — прозорий PNG-атлас ChatGPT Codex.
- Відповідні `.json` — точні прямокутники кадрів, порядок анімації, напрямки та поправки для вирівнювання по землі.
- `sprite-pack.json` — загальна специфікація набору.
- `preview.html` — локальний програвач обох анімацій. Розпакуй архів і відкрий цей файл у браузері; сервер і мережа не потрібні.
- `generation-prompts.json` — опис генерації для подальших варіантів.

## Розмір та Retina

| Параметр | Значення |
| --- | --- |
| PNG-атлас кожного вендора | 1774 × 887 px, RGBA |
| Кількість кадрів | 8, розташування 4 × 2 |
| Прямокутник одного кадру | 442 × 442 px |
| Рекомендований розмір показу | 221 × 221 pt при @2x |
| Початкова частота | 10 кадрів/с |
| Тривалість циклу | 800 мс |
| Тло | Справжня прозорість; кутові пікселі мають alpha = 0 |

221 × 221 pt менше за задану межу 256 × 256 pt. Якщо в застосунку потрібне вікно рівно 256 × 256 pt, постав спрайт 221 × 221 pt по центру: це залишає по 17,5 pt поля з кожного боку й не збільшує растрову графіку. Для компактнішого вигляду можна показувати спрайт у 160–192 pt. Вихідні PNG не збільшувалися й не перемальовувалися під час пакування.

Атлас має нестандартну роздільність, тому використовуй **координати з JSON**, а не ділення ширини зображення на чотири з припущенням про цілі пікселі. Координати відраховуються від верхнього лівого кута. Квадрати кадрів: `x = [1, 444, 888, 1331]`, `y = [1, 444]`, `w = h = 442`.

## Відтворення та напрямки

1. Відтворюй `roll_00` → `roll_07` і повторюй цикл. Рекомендовано почати з 10 FPS; у прев'ю доступні 6–16 FPS.
2. Переміщуй контейнер спрайта горизонтально окремо від зміни кадрів.
3. Для руху праворуч використовуй звичайний кадр. Для руху ліворуч дзеркально відображай **жука разом із кулькою** (`flipX: true`). Порядок кадрів залишається прямим.
4. На межі доступного простору змінюй напрямок і стан дзеркалення. При паузі зупиняй таймер кадрів та переміщення.

У вихідних кадрах жук розташований ліворуч від кульки й повернутий головою вліво: рух праворуч зображено як штовхання кульки задніми ногами, із рухом жука назад. Напрямок анімації описує переміщення всієї пари, а не напрямок голови.

Зворотний напрямок реалізований дзеркаленням під час відтворення; окремого PNG для лівого напрямку не потрібно. У PNG немає тексту, який міг би стати перевернутим.

## Стабільна опора на поверхню

Для кожного кадру в JSON є `renderOffsetPx`. Під час малювання додавай до координати Y значення `renderOffsetPx.y × displaySizePt / 442`. Це компенсує невелику різницю вертикального положення між згенерованими кадрами. Поправки вже застосовані в `preview.html`.

Приклад розрахунку для canvas-подібного рендера:

```js
const scale = displaySizePt / 442;
const dy = frame.renderOffsetPx.y * scale;
context.save();
context.translate(left + displaySizePt / 2, top);
context.scale(direction < 0 ? -1 : 1, 1);
context.drawImage(
  atlas,
  frame.frame.x, frame.frame.y, 442, 442,
  -displaySizePt / 2, dy, displaySizePt, displaySizePt
);
context.restore();
```

`anchorPx` також описує нижню опорну точку. У рушії, який підтримує індивідуальний anchor для кожного кадру, можна вирівнювати за ним **замість** `renderOffsetPx`; одночасне використання обох способів подвоїть поправку.

У macOS/Core Graphics перевір систему координат свого контексту: цей JSON використовує верхній лівий початок. Canvas у прев'ю враховує `devicePixelRatio`, тому 221 CSS px на екрані @2x використовують 442 фізичні пікселі.

## Характер руху

Це цикл із восьми намальованих фаз руху в реалістичному стилі. Обертання фактури кульки не прив'язане фізично до швидкості переміщення по екрану. Прев'ю дає окремі регулятори швидкості та FPS, щоб вибрати приємний темп. Набір містить графіку та локальне прев'ю; інтеграція у вікно поверх робочого столу виконується в застосунку.

Графіку створено вбудованою генерацією та редагуванням зображень. PNG в цьому наборі — незмінені фінальні результати цієї роботи.
